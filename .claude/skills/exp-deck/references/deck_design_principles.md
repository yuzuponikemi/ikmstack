# exp-deck 報告スライド生成原則・詳細ガイド

本ドキュメントは、報告スライド（`.pptx`）を生成・編集する際の詳細なデザイン原則、構成方法、技術仕様および確認手順をまとめています。

---

## 1. 資料作成の背景と目的

他メンバーがGitHubへのアクセス権を持っていない場合があるため、エクスポート可能な成果物が必要となります。
PowerPoint形式（`.pptx`）は、**「①GitHub無しでの閲覧」「②全員での編集」「③GUIによる位置の微調整」**のすべてを満たす唯一のフォーマットです。
`deckgen.py` で初稿を自動生成し、レイアウト調整などの最終仕上げは人間がGUI上で行う分担とします。

### 資料が果たす2つの役割
1. **伝達 (メッセージ管理)**: 読者の疑問に答える順序で並べ、結論と行動を先に提示し、1枚＝1メッセージで「何が言えて何をすべきか」を最短で伝えます。
2. **議論の土台 (ピアレビュー)**: 第三者が検証・反論できるよう、前提条件（手法、データソース、トレードオフ、未解決点）を誠実に開示します。

---

## 2. 技術スライド5大原則 (必須遵守)

1. **プロセスと再現性の明記**: 結果だけでなく「どう得たか」を第三者が再現できる粒度で書きます。図/表は `source`（出典）で来歴を明記し、表紙METAや末尾に MANIFEST の commit SHA や再生成手段を残します。
2. **トレードオフと限界の開示**: メリットだけでなく「制約」「エッジケース」を誠実に提示します。**根拠・提案スライドには、赤（`red`）で「制約/トレードオフ」項目を必ず1つ以上入れます**。
3. **データの誠実さ**: 過度に単純化せず、外れ値を安易に削除しません。N数・誤差範囲・統計的有意性に触れ、「事実」と「推論」を明確に分けます。結論は「Xの条件下でYが言える」のように条件付きで記述します。
4. **必要な複雑さの保持**: システム構成や依存関係などの文脈を省略しません。必要に応じて独立した「全体像/アーキテクチャ」スライドを置きます。
5. **議論への接続**: 結論で終了せず、最後は必ず「Discussion & Future Work」スライドとし、未解決課題やチームで議論したい論点を提示します。

---

## 3. スライドの構成（物語の型）

スライドは読者の疑問の順に並べます：
> **背景 (PLAN.md由来)** → **結論 (条件付き・複数に噛み砕く)** → **行動 (確定した次の一手)** → **根拠 (図+再現性+トレードオフ)** → **確度 (事実/推論の分離、N/誤差)** → **Discussion & Future Work (未解決と技術的な問い)** → 詳細参照先

### 図スライドの出典 (`source`) の記述ルール
- **中間データ**: 何をするデータで、どの一次データ由来かを平易に説明（例: `washparallel_runs.csv`＝生の流体ログから抵抗チェック1回=1行に抽出したデータ）。
- **一次データ**: Drive 上の生ログなどを引用（例: `FluidSysLog_*`）。
- **処理と可視化**: 処理内容はスクリプト名だけでなく日本語で記述（例: 「装置別に集計し robust CV を算出 (生成: scripts/...)」）。

---

## 4. ブランド定義 (テーマスタイル)

標準意匠は単一の定義ソース `brand/tokens.py` から `deckgen` および CSS (`brand.css`) に展開されます。

- **配色**: 
  - プライマリ（見出し）: `#531872` (見出し用 `#6C2A87`)
  - アクセント: 緑 `#4E9D69`
  - 本文: `#313131`
  - フッター帯: `#EAEAEA`
  - 機能色 (制約/トレードオフ): 赤 `#C0392B`
  - `deck.py` で `navy`, `green`, `red`, `gray` と指定すると自動的にこの配色が適用されます。
- **レイアウト**:
  - 表紙: テーマカラーバンド + 背景画像 (`brand/assets/background.png`) + 白タイトル + 左下ロゴ
  - コンテンツ: 白地に濃色タイトル + テーマカラーの細罫。
  - フッター: 左ロゴ + 右ページ番号（出典付きスライドは出典を優先しロゴを省略）。

## 5. 手順と技術仕様

1. **ドキュメント解析**: `REPORT.md`、`PLAN.md`、`figures/` の一覧を読み込み、スライドにする内容を整理します。
2. **`deck.py` の記述**: `experiments/<ID>/deck.py` を新規作成し、ヘッダ定数と `SLIDES` リストを埋めます。
   - スライド型 is `bullets`（箇条書き）または `figure`（左右2カラムまたは図のみ）のいずれか。
   - スライドのメタ属性（`image_side="right"`, `image_w` など）で適宜レイアウト調整。
3. **PowerPoint生成**:
   ```sh
   uv run --with python-pptx .claude/skills/exp-deck/deckgen.py experiments/<ID>/deck.py
   ```
   出力先は `experiments/<ID>/outputs/<OUT_NAME基底>_<YYYYMMDD-HHMM>.pptx`。再生成しても過去の成果物を上書きしません。
4. **目視確認とPDF書き出し**: LibreOffice のヘッドレス変換で PDF と PNG を書き出し、文字溢れやレイアウト崩れを確認します。
5. **Drive配布**: `.pptx` と `.pdf` をGoogle Drive上の実験フォルダにコピーし、関係者がGoogleスライド等で編集可能な状態にします。

### 目視確認用スクリプト(macOS)

前提: `brew install --cask libreoffice` と `brew install poppler`(`pdftoppm` 用)。

```sh
src="experiments/<ID>/outputs"; pptx="$src/<OUT_NAME>"

# 1) pptx -> pdf（LibreOffice のヘッドレス変換）
soffice --headless --convert-to pdf --outdir "$src" "$pptx"

# 2) pdf -> 1スライド1枚の PNG（目視用。preview/ は git 管理外）
mkdir -p "$src/preview"
pdftoppm -png -r 96 "$src/<basename>.pdf" "$src/preview/slide"
```

`preview/` 内のPNGで目視確認後、プレビューディレクトリはコミットせずに削除します。

## 6. Subagent (サブエージェント) を用いた実行規約 (トークン節約)

親エージェントは自身で `REPORT.md` や `PLAN.md` などのドキュメントを直接読み込んではいけません。会話履歴のトークン肥大化を防ぐため、必ず一時的な **Subagent** を起動し、以下の指示テンプレートを用いてタスクを完全に委譲してください。

### Subagent 起動プロンプトテンプレート：
```
以下の手順で、レポートのスライド化およびビルド（exp-deck）を自律的に遂行してください：

1. 対象実験フォルダ: experiments/[実験ID]_[トピック]/
2. 参照原稿:
   - REPORT.md (現状サマリー)
   - PLAN.md (背景・目的の抽出元)

タスク内容：
1. `REPORT.md` と `PLAN.md` を読み込み、スライドにする内容を抽出・整理してください。
2. `experiments/[実験ID]_[トピック]/deck.py` を新規作成（または編集）し、ヘッダ定数と `SLIDES` リストを記述してください。
   - 物語の型 (背景 → 結論 → 行動 → 根拠 → 確度 → Discussion & Future Work) を厳格に適用してください。
   - 根拠・提案スライドには、赤 (red) で「制約/トレードオフ」を最低1つ記述してください。
   - すべての図スライドに出典 (source) を明記してください。
3. 以下のコマンドで PowerPoint スライドを生成してください：
   ```sh
   uv run --with python-pptx .claude/skills/exp-deck/deckgen.py experiments/[実験ID]_[トピック]/deck.py
   ```
4. LibreOffice のヘッドレス変換で PDF/PNG を書き出し(`soffice --headless --convert-to pdf` → `pdftoppm -png`)、スライドの文字溢れやレイアウト崩れがないか目視検証し、崩れがあれば `deck.py` を微調整して再ビルドしてください。
5. 生成された `.pptx` および `.pdf` を Google Drive 上の対象実験フォルダにコピーしてください。

完了後、以下の形式のみで親エージェントに最終報告を行ってください。元ドキュメントのテキストや `deck.py` の全コード等の長大な情報は返さないでください：
---
■ 生成された成果物: [pptx パス] および [pdf パス]
■ スライド構成の概要:
- スライド 1: 表紙
- スライド 2: 背景（...）
- ...
■ 検証ステータス: [レイアウト崩れなし / 要手動微調整 (理由)]
---
```
親エージェントは、Subagent から返された上記のサマリー報告のみをチャット履歴に残し、次の手順に進んでください。
