# runbook-review — E2E Runbook の原子性(実行可能性)を関門にする

手順書③層のうち **① E2E Runbook** のゴールは、**その装置・工具・作業を全く知らない人間が、
判断を一切挟まず、書かれた通りになぞるだけで完了できる**こと。だが執筆者(や LLM)は暗黙に
「取り外す」「調整する」のような**複合・抽象アクション**を1ステップで書いてしまう。現実には
「取り外す」は "部品 A を掴む → ネジ X を反時計回りに N 回転 → B の位置までまっすぐ引く …" という
細かい物理動作の束であり、そこまで割って初めて E2E になる。

このスキルは **① だけ**を対象に、原子性の破れを検出する独立レビューであり、**関門(ゲート)**である。
そして最重要の機能は「直す」ことではなく **足りなさを察知して "完成させない" こと**
(distrust-by-construction)。情報が足りなければレビュワーは**捏造で埋めない** — ⟦FILL⟧ を置き、
その装置を知る人間に埋めさせる。

## 対象は ① E2E Runbook だけ(②③はゲートしない)

- **① 実行**: 原子性を満たすまで割る。未充填の ⟦FILL⟧ が1つでも残る Runbook は**未完成=リリース不可**。
- **② Principles & Triage / ③ Operation Notes**: 対象外。判断・暗黙知を扱う層で、完結を強制しない
  (③は追記型で永遠に未完でよい)。②③の欠落は readability-review や OPEN 明示で扱う。

## 核となる仕掛け(なぜ効くか)

レビュー用サブエージェントに **対象 Runbook 1 本だけ** を渡し、②③・元手順・
この会話を**見せない**。ペルソナは「**その装置・工具・部品を一度も見たことがない実行者**」。
手は動かせて字は読めるが、部品の在り処も工具の形も力加減も方向も知らない。
このペルソナに**文字通り実行させる**と、知識で補えるステップは補えず、**原子性の破れが自動的に露出**する。
維持するチェックリストは要らない(隔離+無知ペルソナそのものが判定器)。

> readability-review との違い: あちらは「他分野の**新人**(一般語は知る)が**意味**を取れるか」。
> こちらは「装置を**全く知らない**実行者が**物理的に実行**できるか」。無知の度合いが一段深い。

## 原子性テスト(各ステップがこれを満たすか)

1. **単一の物理プリミティブか**: 動作は1つ(掴む/置く/差す/抜く/回す/押す/A→B へ動かす等)。
   「取り外す」「セットする」「調整する」「交換する」のような**複合動詞は不合格** → 割る。
2. **対象が同定可能か**: どの部品か(P/N・明確な外見・位置)、どの工具か。「ネジ」でなく「どのネジ」。
3. **量・方向が明示されているか**: 何回転/どちら向き/どこまで/どのくらいの力・時間。効く所だけでよい。
4. **隠れた判断が無いか**: 「適切に」「確認する(方法が無い)」「必要なら」は判断を要求している → 方法を書くか ② へ。
5. **完了が観測可能か**: 何を見れば/聞けば/測れば「できた」と分かるか。

## ⟦FILL⟧ プレースホルダ規約(関門の実体)

破れが見つかったら、レビュワーは**答えを創作せず**、その場に穴を可視化する:

- テキスト: `⟦FILL: <何が足りないか> — 記入者: <埋めるべき人/役割>⟧`
- HTML: `<span class="fill">⟦FILL: … — 記入者: …⟧</span>`(赤系で目立つ。下の CSS 参照)
- **未充填の ⟦FILL⟧ が残る Runbook は「未完成=リリース不可」**。将来 `grep -R "⟦FILL"` を
  pre-commit ゲート化してよい(現状は可視マーカ+本スキルの判定で運用)。

HTML に埋める最小 CSS(テンプレに同梱済。無い場合は追加):
```css
.fill{background:rgba(192,57,43,.12);color:#c0392b;border:1px dashed #c0392b;
      border-radius:5px;padding:0 6px;font-weight:700;}
```

## 手順

1. **対象 Runbook を特定**(引数、または直近で書いた ① E2E Runbook)。複数なら 1 本ずつ。
2. **隔離レビュー**: サブエージェント 1 体を起動し、**その Runbook の本文(ステップ)だけ**を渡す。
   - **②③・元手順・会話・関連文書を渡さない**(渡すと無知ペルソナが壊れる = 最重要アンチパターン)。
   - 指示: 上記「無知な実行者」を演じ、**各ステップを上から文字通り実行しようとする**。
     実行できない所を、原子性テスト1〜5のどれで詰まったかと共に**列挙**する。
     各項目 `{ステップ番号, 詰まった理由(どのテストか), 何が分かれば実行できるか, 推奨する分割/追記}`。
   - 出力は**指摘リストのみ**。本文の書き換えも、欠落の推測補完も**しない**。
3. **取捨**: 主エージェントが精査。過剰分割(現場常識で自明な粒度)を捨て、正当な破れを残す。
   迷ったら「その装置を初めて触る人がこの1文だけで手を動かせるか」で決める。
4. **反映(捏造禁止)**: 正当な指摘ごとに、
   - **答えを知っている場合**(元手順・確定情報にある): その粒度まで**ステップを割って書く**。
   - **答えを知らない/情報が無い場合**: **⟦FILL⟧ を置く**。ここで埋めた気になって滑らかな文を
     でっち上げない — それが今回直したい失敗そのもの。
5. **再チェック**: 大きく割った/⟦FILL⟧ を足したら、同じ隔離レビューをもう一度回して残りを見る。
6. **報告**: 指摘件数・採用/棄却・割ったステップ数・残った ⟦FILL⟧ 件数(=ゲート状態)を表で示す。
   ⟦FILL⟧ が残る限り「この Runbook は未完成(誰が何を埋めるべきか)」と明言する。

## ペルソナ(サブエージェントへの指示の芯)

「あなたはこの装置を一度も見たことがない。部品の場所・工具の形・回す向き・力加減・正常な見た目を
一切知らない。書かれた文字だけが頼り。各ステップを順に、文字通り手を動かして実行しようとせよ。
自分の推測や一般常識で穴を埋めてはいけない。手が止まった所を全部報告せよ。」

## アンチパターン

- **足りない手順をレビュワー(や主エージェント)が推測で埋める** → 今回の元凶。必ず ⟦FILL⟧。
- **サブエージェントに ②③・元手順を渡す** → 無知ペルソナが壊れ、破れを検出できない。1 本だけ。
- **②③まで原子性ゲートにかける** → 判断・暗黙知を殺す。ゲートは ① だけ。
- **過剰分割**(「息を吸う」レベルまで割る) → ノイズ。基準は「その装置の初見者が手を動かせるか」。
- **⟦FILL⟧ を残したまま "完成" と報告** → ゲートの意味が消える。残件数を必ず明示する。
