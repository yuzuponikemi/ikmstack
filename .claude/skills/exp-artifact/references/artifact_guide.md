# exp-artifact 詳細ガイド — 記事の型・図の選び方・検証

`SKILL.md` の Step 4〜6 の中身。**読む順は「型 → 図 → 見た目 → 検証」。**

---

## 1. 記事の型

実験レポートは論文ではないので、論文の型（序論→方法→結果→考察）に押し込むと読めなくなる。
実験の読み物としての型は次の並びで、**結論が先、根拠は後、そして「何を信じるのをやめたか」が中心**。

| 節 | 中身 | 出どころ |
|---|---|---|
| マストヘッド | 実験ID・題・1段落の要旨・状態と期間 | `skeleton.experiment` |
| **主要な数（3枚程度）** | この実験を一言で表す数値。ゼロなら**ゼロを堂々と出す** | `REPORT.md` の結論 |
| いま報告できること | 現在の結論と、それを弱めている理由 | `REPORT.md` 結論節 |
| 判定の枠組み | 実験が事前に固定した定義・条件 | `PLAN.md` |
| 証拠の形 | 問い→測定→条件→観測→対抗仮説 の系統図 | `REPORT.md` |
| **測った数字（図）** | 図3〜6点。各図に出典行 | 一次記録 |
| **撤回台帳** | 信じるのをやめた主張の全件 | `skeleton.retractions` |
| 限界と次 | 重い順に並べた限界、次の一手 | `REPORT.md` |
| 一次記録の索引 | 全件。訂正した回は視覚的に区別する | `skeleton.records` |

**中心装置は撤回台帳。** 進行中の実験ほど「まだ答えが出ていない」ので、結果の節は薄い。
一方で撤回台帳は厚く、しかも他の実験にも持ち出せる知見を含んでいることが多い。
記事の重心をそちらに置くと、未決の実験でも読み物として成立する。

**一次記録の索引は、題だけ並べても読み物になる。** 一次記録の題は結論を1行で書く規律に
なっているので、順に並べると実験の筋がそのまま出る。`corrects` を持つ回を太字にすると、
「どこで前の結論が覆ったか」が索引だけで読める。

### 書かないこと

- 実験の**過程の自慢**（「〜も試した」の羅列）。覆った経緯は一次記録の側にある。
- `REPORT.md` の**全文写経**。記事は現在の正だけを置く。
- 断定できない数値の断定。潰せなかった数値は落とすか「暫定」と明記する。

## 2. 何を図にするか

**図にする価値があるのは「表のままでは読み取れない関係」だけ。** 数値を1つ示すだけなら
大きな数字（stat tile）のほうが速い。判断の順序:

1. **比較の向きが逆転している** → 図が最も効く。前半と後半で向きが逆になった、
   条件を足したら片側だけ落ちた、など。表では読み手が引き算をしないと見えない。
2. **区間が重なっている** → 点推定だけの表は「差がある」と読ませてしまう。
   ドット＋95%信頼区間にすると、重なりが目で分かる。
3. **段階や順位がある** → 横棒。判定者の誤検出率のように「使える／使えない」を
   同時に見せるなら、状態ラベルを軸ラベルの下に添える（色だけで区別しない）。
4. **上のどれでもない** → 表のままにする。図にしない判断も設計である。

### 図の作り方の規律

- **系列は2つまで**にする。3つ目からは検証器が WARN を出す組み合わせが増え、
  直接ラベルが必須になる。分けられるなら図を2枚にする。
- **数値は直接ラベルする**（`9/12` のように分子分母のまま）。パーセントだけにしない。
  分母が違う比較は、分母を見せないと読者が検算できない。
- **各図に出典行**（`出典 R031 §2（Fisher 正確検定、両側）`）。検定名と両側/片側まで書く。
- 派生値（差・区間・p値）は、**元の分子分母から再計算できる形**で示す。

## 3. 見た目の規律

- **配色はラボのブランドを引く**（`SKILL.md` Step 4）。実験ごとに配色を変えない。
  紫がラボの色、緑=確定、橙=留保、赤=撤回。この意味付けは記事間で固定する。
- **中立色は紫寄りに倒す**。純グレーは「決めていない」ように見える。
- **書体は3役**: 見出し（明朝＝活版調で記録らしさを出す）／本文（ゴシック、日本語の密度に耐えるもの）／
  数値とID（等幅、`font-variant-numeric: tabular-nums`）。Google Fonts は Artifact の
  CSP で唯一許可された外部ホストなので、`<link>` で直接読める。
- **構造装置は情報を持たせる**。一次記録IDを左ガターに通すのは、実験のすべての主張が
  番号付きの記録に紐づくという事実の表現。意味の無い連番（01/02/03）は置かない。

## 4. テーマ3状態（Artifact 固有の罠）

閲覧者のテーマは**3状態**ある。明示選択が `data-theme="dark"` / `="light"` を root に付け、
既定の「システム追従」は**何も付けない**。したがって:

- 素の `:root` に**ライトの全トークン**を定義する
- `@media (prefers-color-scheme: dark)` は `:root:not([data-theme="light"])` で囲む
- `:root[data-theme="dark"]` でもう一度上書きする
- **`body` に必ずトークン由来の `background` を置く**（透明だとホスト側の地を借りて、
  片方のテーマで本文が読めなくなる）
- 色をメディアクエリや `[data-theme]` の中「だけ」で定義しない（無印状態で適用されない）

## 5. 検証

### ローカル描画（公開前に必ず）

`SKILL.md` Step 5 のコマンドで、**ライト・ダーク・狭幅**の3通りを見る。

長い記事は1枚のスクリーンショットに収まらない。節ごとに
`<style>#other-section{display:none}</style>` を差し込んだ一時プレビューを作って撮ると、
見たい節だけを原寸で確認できる。

### 横スクロールの実測（目視で判断しない）

```js
// 380px の iframe に入れて測る
const d = document.getElementById('f').contentDocument;
d.documentElement.clientWidth === d.documentElement.scrollWidth  // true なら横スクロール無し
```

**headless Chrome の最小ウィンドウ幅は 500px。** `--window-size=390` は画像を切るだけで、
レイアウトは 500px で組まれる。スクショで本文が切れていても、それはクロップかもしれない。
**実測してから直す**（そうしないと、存在しない不具合を「直して」別の不具合を入れる）。

幅の広い要素（表・コードブロック・図）は、**それ自身の `overflow-x: auto` の中で**
スクロールさせる。`body` に `overflow-x: hidden` を掛けて隠すのは対処ではない。

### 実験との突き合わせ

`SKILL.md` Step 6。捏造引用と出典欠落だけを見る、軽い機械検査。

## 6. 実例: E013（2026-09-06）

進行中・図ゼロ・一次記録33本・主問い未決という、いちばん記事化しにくい形。

**効いたこと**

- **ゼロを3枚並べて始めた**（討論側から出た頑健な変形 0件／3条件を満たす命題 0件／
  中立な判定者 0人）。否定的な結果を薄めずに出すほうが、読み物として強い。
- **表を図にしたのが純増だった。** この実験は図が1枚も無く、数値はすべて表の中にあった。
  前半と後半で向きが逆転した比較（9/12 対 4/12 → 5/12 対 6/12）は、図にして初めて
  「n=12 で比べてはいけない」が一目で伝わる。
- **撤回台帳を中心に置いた。** 結果の節より情報量が多く、しかも他実験に持ち出せる。

**やらかしたこと（このスキルが防ぐ対象）**

- 撤回台帳を `REPORT.md` の散文から手で転記し、**「16件のうち11件は自分で見つけた」という
  出どころの無い数字**を書いた。フロントマターを機械で引けば14件・全件 `self`。
  → だから `skeleton` を先に回す。
- 狭幅のスクリーンショットが切れているのを見てレイアウト不具合と判断し、
  `overflow-x: hidden` を入れた。実測すると横スクロールは元から無かった（クロップだった）。
  → だから測ってから直す。ただし同じ検査で**本物のバグも1つ見つかった**
  （1カラム時に `grid-column: 2` が暗黙の2列目を作っていた）ので、検査自体は正しい。
