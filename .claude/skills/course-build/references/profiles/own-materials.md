# プロファイル: 自分たちの資料に紐づける(own-materials)
<!-- slots: ANCHOR=自分たちの実例 | ANCHOR_HEADING=実際の資料ではこう使われている | WHY_LABEL=なぜこの方法なのか | CASES_HEADING=実例で読む -->

自分たちの装置・システム・業務データ・報告書・論文に出てくる実際の数値や図を錨にして、一般の知識(統計・機械学習・信号処理・設計の考え方など)を学ぶコース。
例: 統計を、自社装置の分類スコアと ROC 曲線、品質管理の判定基準、実験レポートの p 値で学ぶ。装置や自分たちのシステムそのものを教える場合もこの型を使う(その場合は一般知識の節を減らし、仕様の読み方と設計の理由を厚くする)。

| 枠 | 値 |
|---|---|
| 置き場所 | コースのフォルダ(組織の文書管理の規約に従う)。共有範囲が限られる資料を載せるときは、公開先の共有範囲も合わせて管理する |
| `{ANCHOR}` | 実データ・実験レポートの数値・論文の図表・仕様書の値 |
| `{ANCHOR_HEADING}` | 実際の資料ではこう使われている |
| `{WHY_LABEL}` | なぜこの方法なのか(装置・システムなら「設計の理由」) |
| `{CASES_HEADING}` | 実例で読む(装置・システムなら「実機で見るとこうなる」) |
| 一次資料 | (a) 概念の定義: 標準教科書(節番号で参照、転載しない)/ (b) 実例: 自分たちのレポート・仕様書・ログ・論文(path:行、図番号、本文の節) |
| ダイジェスト分割の目安 | S1 範囲と章対応 / S2 記法の約束と流儀差 / S3 頻出の問われ方・誤答の型 / S4 実例の台帳(トピック × 実例 × path:行 × 数値 × 注意点)/ 必要なら S5 論文の読み解き |
| 食い違い台帳 | 記法の流儀差に加え、**元資料の統計的な扱いの曖昧さ**(例: p 値の読み方、n が小さい比較、根拠の無い閾値、資料内の数値の食い違い)。元資料を直す候補は「訂正候補」として別ファイル(`authoring/review/corrections.md`)に集め、教材の中では両論併記する |
| 再計算の方法 | Python(numpy/scipy)で全数値を再計算。元データを使う計算は、データのパスと抽出条件を `authoring/verify/` に残す(データ本体はリポジトリに置かない) |
| `math` | katex(数式を使うコース) |
| 事例 `.case` の出典 | レポートの path:行、文書名と節、論文の図番号 |
| 完了後 | 元資料の訂正候補を担当者に渡す。確定した知見は組織の知識ベースへ |

注意:
- 実例は「正解の例」とは限らない。統計的に弱い主張を見つけたら教材の題材(誤用の事例)にし、断定せず `推測` / `確認が必要` を付ける。
- 元資料の画像は貼らず描き直す(共有範囲の限られた図が公開物に混ざるのを防ぐ)。
- 資料の全ページを通読してからダイジェストを書く。要約や目次だけから書くと、1 章あたりの内容が薄い「要約教材」になる。
- 試験対策も兼ねる場合は、各章に「試験での問われ方」の小節を残す(exam-cert の S1・S3 を流用)。
