# 章執筆仕様(course-build 共通)

装置の光学教材と統計の教材を作った経験から、分野に依存しない形にまとめた章執筆仕様。
コースごとに `<course>/authoring/CHAPTER-SPEC.md` へコピーし、§0 の差し替え枠を**プロファイル**(`profiles/*.md`)で埋めてから執筆に入る。
**この仕様の必須要素をすべて満たした章だけを完成とみなす。** 満たせない要素は削らず「未完成」と書いて報告する。

## 0. 差し替え枠(プロファイルで決める)

| 枠 | 意味 | 例: 装置・システム | 例: 資格試験 |
|---|---|---|---|
| `{ANCHOR}` | 計算例・図の初期値に使う「具体の錨」 | 装置の実数値 | 出題範囲内の典型設定・公開データ(own-materials では自分たちの実データ・レポートの図) |
| `{ANCHOR_HEADING}`(`h2#anchor`) | 錨との対応を示す節の見出し | 装置での実装 | 試験での問われ方 |
| `{WHY_LABEL}`(`.why`) | 「なぜそうなっているか」の箱の名前 | 設計の理由 | なぜこの方法なのか |
| `{CASES_HEADING}`(`h2#cases`) | 事例の節の見出し | 実機で見るとこうなる | よくある誤答・誤用 |
| 一次資料 | ダイジェスト S1〜Sn の元 | 設計資料・仕様書・実験 | 出題範囲表・標準教科書(節番号で参照) |
| 食い違い台帳 | 資料間で割れている事項 | 数値の食い違い | 定義・記法・パラメータ化の流儀差 |

## 1. 読者と到達点

- 読者と前提知識はコースの `PLAN.md` に書く(例: 「高校物理レベル」「大学教養の微積分・線形代数」)。式の水準もそこで決める。
- 到達点: 章を読み終えたら「`{ANCHOR}` の数値で計算できる」「方法・設計の理由を説明できる」「事例をその章の概念で説明できる」。用語を知っているだけの状態をゴールにしない。

## 2. ファイルと技術要件

- 正本は `chapters/Cxx.html`(1 章 = 1 ファイル、単独で開ける HTML)。Markdown 版は作らない(二重管理で片方が痩せる)。
- 雛形: `chapters/_template.html`。head・構造・クラス名・**h2 の id**(`intro` / `p1`〜`p6` / `anchor` / `cases` / `quiz` / `summary` / `glossary` / `refs`)はこれに合わせる(`check_chapter.py` が id で検査する)。
  - `<body data-ch="Cxx">`、`<div class="wrap">` の中に `header.ch` → `nav.intoc`(空でよい)→ `main` → `footer`。
  - `../assets/course-config.js` → `../assets/course.js` の順に `defer` で読む。章固有のスクリプトは本文末尾にインラインで置き、`DOMContentLoaded` の中で `TC.*` を使う(先に走ると `TC` 未定義)。
  - 外部ライブラリは使わない。例外は Google Fonts と、プロファイルが `math: katex` のときの KaTeX 0.16.9(cdnjs、雛形の 3 行)だけ。localStorage に依存しない。
  - 幅 360px で横スクロールが出ないこと(表は `.tbl` で包む、SVG は viewBox 指定で幅 100%、長い式は `.eq` か display 数式)。
- 文体は「です・ます」。コードコメントは英語。
- 図はすべて **自作のインライン SVG / canvas**。他者の図・本文・問題は貼らない(著作権)。資料の図を参考にした場合は描き直し、figcaption に「〇〇(S1 §D)を基に作図」と書く。
- SVG の文字色は `fill="var(--c1)"` 属性か `style="fill:…"` で付ける。`.paper` / `.stage` の既定色は fill 属性の無い text にだけ掛かる。本文・キャプションで色名(赤・青)を使うなら実際の描画色と一致させる(統計コースでは古い CSS が属性を上書きし、凡例の赤と青が両方黒になっていた)。
  - 暗い台の図は `figure > .stage`、紙面風のグラフは `figure > .paper`。系列色は `var(--c1)`〜`var(--c5)`(レーザ光路の図などは `--b405` `--b488` `--b637`)。両テーマで読めること。

## 2.5 記法と組版(数式を含むコース。`check_chapter.py` が機械で検査する)

読者が「同じ記号が場所によって違う見た目」で迷わないことが目的。数理が正しくても、ここが崩れると読みにくい教材になる。

1. **記号は必ず数式で書く**: 変数・パラメータ・ギリシャ文字・ハット・バーは、地の文・表・確認問題・図のキャプションでも `\( \)` に入れる(✗ `λ = 2 の指数分布` → ✓ `\(\lambda = 2\) の指数分布`)。「n = 25」のような代入も同じ。地の文に Unicode のギリシャ文字や合成のハット(λ̂)を書かない。
2. **演算子はマクロだけ**: `\E` `\Var` `\Cov` `\Corr` `\SE` `\MSE` `\Bias` `\AIC` `\BIC` `\logit` `\argmax` `\iid` `\T`(転置)`\dd`(微分の d)。すべて立体。`\operatorname{Var}`・`\mathrm{Var}`・素の `Var(`・素の `E[` は使わない。マクロは `course.js` の `TC.MATH_MACROS` が正本で、足すときはコースの `course-config.js` の `mathMacros` に書く。
3. **数式の描画は course.js に任せる**: 章のスクリプトで `renderMathInElement` を呼ばない(マクロが効かなくなる)。LAB が数式を含む文字列を後から差し込むときは `TC.renderMath(要素)`。
4. **計算例は数式で書く**: `<div class="calc">\[\begin{aligned} … \end{aligned}\]</div>`。等号で揃え、途中式を省かない。`pre.calc`(等幅)は記号を含まない数値だけの表に限る。
5. **数式を使えない場所**(フォームのラベル・読み値・SVG・canvas): 変数は `<span class="m">λ</span>`(SVG は `<text class="m">`、canvas は `font: italic 14px KaTeX_Math, serif`)で、数式と同じ斜体のセリフ体にする。演算子名・数字は `class="mu"`(立体)。
6. **太字・ベクトル・行列**: ベクトルは `\boldsymbol{x}`、行列は大文字 `X`(太字にしない)で統一し、章の冒頭か用語集に記法の約束を書く。確率は `P(\cdot)`、分布名は立体 `\Normal(\mu, \sigma^2)`。
7. **大きさ**: 本文中の分数は `\tfrac`、総和は `\textstyle\sum`。行内で背の高い式を作らない(行間が崩れる)。複雑な式は display にする。

## 3. 必須構成(この順)

| # | 要素 | 中身の基準 |
|---|---|---|
| 0 | ヘッダ | eyebrow(`<コースタグ> · Part n · Cxx`。Part の区切りはコースの README/PLAN の章立て表で定義する)、h1、`.goals` に到達目標 3〜5 個(「〜を計算できる」「〜を説明できる」の検証可能な形)、`.meta` に所要時間・前提章・主な出典 |
| 1 | 導入 `h2#intro` | **`{ANCHOR}` で実際に出会う疑問・現象 1 つ**から始め、この章を読むと答えられることを示す |
| 2 | 原理 `h2#p1`〜 × 3〜6 | 各節: 出発点(前提知識)→ 概念 → **図 1 枚以上** → **計算例 `.ex`(`{ANCHOR}` の数値で、途中式を `pre.calc` か数式で全部書く)** → よくある誤解 `.mis`(該当するとき) |
| 3 | `{ANCHOR_HEADING}` `h2#anchor` | 一次資料ダイジェストの事実を、表・図で**具体的に**。数値・条件には出典(`.src`)を付ける |
| 4 | `{WHY_LABEL}` `.why` × 2 以上 | 「なぜこの値・この方法なのか」をトレードオフで説明。資料に根拠が無い説明は `推測` バッジ |
| 5 | `{CASES_HEADING}` `h2#cases` | **事例 2 件以上** `.case`。状況 → 数値 → 機序 → 確度。この章の概念で事例がどう説明できるかを明示 |
| 6 | インタラクティブ図 `.lab` × **3〜5** | 原理節に埋め込む操作図(canvas アニメーション・ドラッグ・スライダ・シミュレーション)。静的図の置き換えでなく「動かすと因果が見える」こと。1 つ以上は `{ANCHOR}` の値を初期値にする。各図に「やってみること」2〜3 個と `.obs`(何に気づくべきか)。簡略化したモデルは「模式」と明記 |
| 7 | 確認問題 `h2#quiz` | `ol.quiz` で **8 問以上**: 基本 3 問以上、計算 3 問以上、応用・診断 2 問以上(`.lv` に「基本」「計算」「応用」「診断」)。解答は答えだけでなく**理由・途中式**まで、`<details>` に入れる |
| 8 | まとめ `h2#summary` | 「この章で言えるようになったこと」5〜7 項目 |
| 9 | 用語集 `h2#glossary` | `dl.gloss`、章内の初出用語すべて |
| 10 | 参考資料 `h2#refs` | 一次資料ダイジェストの該当節と、外部(教科書・論文・無料教材) |

分量の目安: 本文(スクリプト・SVG を除く)で日本語 9,000〜16,000 字。インタラクティブ図のスクリプトは量の制限なし。上表の要素を欠く短さは不可。

## 4. 証拠と数値の規律

- 錨の数値・事実は `authoring/sources/S1〜Sn` にあるものだけを使う。無い数値を使う場合は一次資料を自分で確認して出典を付ける。推測で数値を作らない。
- 確定・推測・不明を区別する: `<span class="badge b-fact">確定</span>` / `b-hyp` 推測 / `b-unk` 確認が必要。
- 食い違い台帳(コースの `REPORT.md`)の未解決事項は単一値にせず、`<span class="badge b-c">S2-C1</span>` を付けて両論併記する(台帳の番号は章番号 C01〜 と紛れないよう `S2-` などの接頭辞を付ける)。新しい食い違いを見つけたら REPORT.md は編集せず、完了報告に書く(台帳の編集者は 1 人)。
- 一般法則と錨の値を混同しない(例: 1.22λ/NA は一般式、0.618 µm は条件を入れた値)。
- **計算問題・計算例・操作図の読み値はすべて独立に再計算する**(プロファイルが指定する方法で。例: Python/scipy、モンテカルロ)。再計算した値と手順を完了報告に書く。

## 6. インタラクティブ図の品質基準

- 描画は canvas(アニメーションは `requestAnimationFrame`、画面外では停止してよい)または SVG + JS。`TC.canvas(cv, h)` で DPR 対応のサイズ設定ができる。乱数は `TC.rng(seed)` / `TC.randn(u)` で再現可能にする。
- 操作に即時に反応し(60fps 目安)、読み値(`.readout`)を数値と単位で併記する。
- 動きのある現象は動かして見せる(例: 標本が 1 つずつ落ちてヒストグラムが育つ、信頼区間が 100 本並び外れたものが色で分かる)。
- 初期状態で既に意味のある絵が出ていること。リセットボタンを付ける。
- リサイズに追従し、スマホ幅で操作できる(タッチ対応、ボタンは指で押せる大きさ)。`TC.reducedMotion()` が真ならアニメを止める。
- 章内で id に接頭辞を付ける(例: `c03-ci-`)。
