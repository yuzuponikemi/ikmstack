# exp-checkpoint チェックポイント同期手順・詳細ガイド

本ドキュメントは、作業の区切り（チェックポイント）において、実験ドキュメントやログを同期・最新化するための詳細な手順を定めています。

---

## 1. リビング文書 (大文字系) の同期規約

作業が一区切りついたら、必ず以下のリビング文書（大文字系ファイル）を順に確認・更新します。更新または変更がないことを確認した履歴（表など）を、最終的にユーザーへ報告します。

| 文書 | 更新判断 | 記述内容 |
| :--- | :--- | :--- |
| **REPORT.md** | **毎回必須** | 現状サマリー、結論（1行）、確定した事実（結果）、考察（仮説）、**次のアクション**、フロントマターの `status`/`summary`。事実と仮説は混同せず、覆った過去の結論は残しません。 |
| **PLAN.md** | 計画や仮説が変動した際 | 実験の枠組み、次にやることを現実に合わせて更新。 |
| **DECISIONS.md** | 方針転換があった長期実験のみ | なぜ変更したかの経緯を追記（追記型、R番号なし）。不要な実験では作成しません。 |
| **MANIFEST.md** | 新データやコミットSHA更新時 | 隣接リポジトリの最新 commit SHA や Google Drive のパスを反映。 |

---

## 2. チェックポイント処理の一巡手順

1. **対象実験の特定**:
   - 今回の作業で変更や測定を行った実験ディレクトリを特定します。
2. **一次記録の確認**:
   - 新しい検証結果があれば、`reports/E###-R###_...` としてレポート化されているか確認します（採番とフロントマターは `exp-report` スキルに従う）。
   - 画像などのバイナリファイルが Git に誤って追加されていないか（三大原則#1）確認します。
3. **大文字系リビング文書の更新**:
   - 上記の規約に基づき、`REPORT.md` / `PLAN.md` / `DECISIONS.md` / `MANIFEST.md` を一巡して更新または確認します。
4. **インデックスの再生成**:
   - `python tools/report_meta.py` を実行して `INDEX.md` を更新し、`python tools/report_meta.py --check` でエラーがないことを確認します。
5. **日次ログの作成**:
   - `logs/<YYYY>/<YYYY-MM-DD>_<topic>.md` に、当日の作業概要を `lab-log` 規約（目的/やったこと/わかったこと/次にやること）に従って記録します。
6. **最終報告**:
   - 更新したリビング文書、または「変更なし」を確認した旨を整理し、表形式でユーザーに提示します。
