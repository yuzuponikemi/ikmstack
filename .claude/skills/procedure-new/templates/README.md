# 手順書ひな型（3層トリロジー）

手順書を目的別の3層に分けて書くための、**自己完結HTMLひな型**。
各ファイルは外部依存なし（CSS/JSインライン）・ライト/ダーク対応・印刷/PDF可。
複製して `[[...]]` プレースホルダを埋め、`<div class="authoring-guide">` の枠を消すだけ。

| ファイル | 層 | 色 | 何を書くか | 何を書かないか |
|---|---|---|---|---|
| `e2e-runbook.template.html` | ① 実行 | 緑 | 一本道の手順（QRH形式・1文1アクション） | Why・手触り・トラブル判断 |
| `principles-triage.template.html` | ② 橋渡し | 橙 | なぜ・異常時の判断・優先順位・エスカレーション | 個別の具体手順 |
| `operation-notes.template.html` | ③ 統合 | 紫 | 背景・五感・罠・応用（暗黙知ログ・追記型） | 一本道の実行手順 |

## 使い方

1. 書きたい手順が**どの層か**を決める（判断に迷ったら下の一言テストへ）。
2. 対応する `*.template.html` を複製し、実手順名にリネーム（例 `chip-swap.runbook.html`）。
3. `[[...]]` を埋め、冒頭 HTML コメントの記述ルールに従う。
4. `authoring-guide` の枠と、使わないサンプルブロックを削除する。
5. 3層をセットで作るときは、各ファイル内 `nav` と `xlinks` の `[[...html]]` を
   実ファイル名に置き換えて相互リンクをつなぐ。

## どの層かを見分ける一言テスト

- **手が止まらず最後までなぞれれば足りる** → ① E2E Runbook
- **「なぜ？」「異常時どうする？」「誰を呼ぶ？」に答える** → ② Principles & Triage
- **「コツ」「勘所」「あの時ハマった」を残す** → ③ Operation Notes

> 罠の核心は「①だけ作って、②③を①に混ぜる」こと。混ぜると①が読めなくなり、
> 「手順書はあるのに動かない」を生む。**分けて薄く、相互リンクで繋ぐ。**

## ① の関門：原子性ゲート（runbook-review）

① だけは「その装置を**全く知らない人**が判断なしになぞれる」粒度が要る。「取り外す」等の複合動詞は
物理プリミティブまで割る。**足りなければ推測で埋めず** `⟦FILL: 何が足りないか — 記入者: 役割⟧` を置く。
**⟦FILL⟧ が残る① は未完成（リリース不可）。** 判定は `runbook-review` スキル
（隔離サブエージェントに①を1本だけ渡す）。実例 → `../examples/chip-holder-replacement/`
（D1000210 は 0/17 で、実は初見者向け①でなく技術者向けチェックリストだったと判明）。

## スタイルの出所

配色は exp-deck のブランドトークン（`.claude/skills/exp-deck/brand/tokens.py`）に準拠。
ひな型は依存を持たないよう、トークンを各 HTML に**インライン化**している
（ブランド更新時は各ひな型の `:root` を追随させる）。
